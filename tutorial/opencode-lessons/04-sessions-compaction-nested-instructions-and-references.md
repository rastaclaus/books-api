## Цель урока

- Освоить управление сессиями в TUI: создание `/new` (`Ctrl+X N`), список `/sessions` (`Ctrl+X L`), недавние сессии и проекты через `Ctrl+O`, вкладки сессий `Ctrl+Tab` / `Ctrl+Shift+Tab`, переименование `Ctrl+R` и закрепление `Ctrl+F` — а также те же операции из второго терминала через `opencode session list / export / import / delete`.

- Применить всё это на практике: вложенный `AGENTS.md` для доменного пакета, продуктовая спецификация квот скачивания через `references`, и сущность `Reader` с антибот-квотами, реализованная агентом в **чистой** сессии.

## Теория-минимум: сессии, compaction и долговременный контекст

### Сессии в TUI

Каждый разговор с агентом — это **сессия**, которой владеет фоновый сервер. TUI — лишь клиент, поэтому сессии живут независимо от открытых терминалов.

| Действие | Клавиши | Команда |
|---|---|---|
| Новая сессия | `Ctrl+X`, затем `N` | `/new` |
| Список всех сессий | `Ctrl+X`, затем `L` | `/sessions` |
| Недавние сессии и проекты | `Ctrl+O` | — |
| Следующая / предыдущая вкладка | `Ctrl+Tab` / `Ctrl+Shift+Tab` | — |
| Переименовать сессию | `Ctrl+R` | — |
| Закрепить/открепить в списке | `Ctrl+F` | — |
| Компакция сессии | `Ctrl+X`, затем `C` | `/compact` |
| Закрыть вкладку | `Ctrl+X`, затем `W` | — |

Вкладки сессий включены по умолчанию: можно держать открытыми несколько сессий одновременно и переключаться между ними, а `Ctrl+Shift+T` переоткрывает последнюю закрытую вкладку.

### Сессии из CLI

Во втором терминале теми же сессиями управляет CLI (они лежат в общей БД сервера):

```bash
opencode session list                        # список сессий
opencode session list --max-count 20 --format json
opencode session export ses_xxxx             # выгрузка сессии в JSON
opencode session export ses_xxxx --sanitize  # с маскированием чувствительных данных
opencode session import session.json         # импорт сессии из файла
opencode session delete ses_xxxx             # удаление сессии и её дочерних сессий
```

### Compaction: как длинная сессия не упирается в контекст

Когда сессия приближается к лимиту контекста модели, OpenCode **сжимает** её: старая переписка заменяется саммари, а последние ~15000 токенов остаются рядом с ним дословно — точные свежие детали не теряются.

```
before   [ system prompt ][ старая переписка ............ ][ последние 15k ][ текущая работа ]
after    [ system prompt ][ саммари старого ][ последние 15k ][ текущая работа ]
```

Настройка — секция `compaction` в любом конфиге OpenCode:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,            // компакция у лимита контекста включена по умолчанию
    "background": true,      // саммари пишется заранее, чтобы не ждать в момент сжатия
    "keep": { "tokens": 15000 }, // сколько свежих токенов оставлять дословно
    "buffer": "15%",         // доля окна модели, удерживаемая свободной (минимум 16k)
  },
}
```

| Поле | По умолчанию | Поведение |
|---|---|---|
| `auto` | `true` | Сжимает автоматически у лимита контекста |
| `background` | `true` | Пишет саммари заранее, в фоне, пока сессия продолжает работу |
| `keep.tokens` | `15000` | Сколько свежей переписки оставить рядом с саммари |
| `buffer` | `"15%"`, минимум 16k | Свободная доля окна; компакция стартует, когда разговор занимает остальное |

Запросить компакцию вручную можно в любой момент — даже на короткой истории: `Ctrl+X C` в TUI. Ручная компакция работает и при `auto: false`.

**Компакция — lossy.** Саммари резюмирует старую переписку: детали формулировок, промежуточные договорённости и «устные» решения могут исчезнуть. Отсюда главный вывод урока:

> Критичные правила проекта — границы архитектуры, команды проверки, продуктовые ограничения — должны жить в **артефактах** (`AGENTS.md`, `references`, инструкции из конфига), которые подаются агенту при каждом запросе независимо от длины сессии, а не в договорённостях «из чата».

### Вложенные `AGENTS.md`: контекст там, где код

`AGENTS.md` можно класть не только в корень: файл в подкаталоге описывает правила именно этой области кода. Вложенные файлы загружаются **лениво**: агент обнаруживает их, когда читает файлы или листит каталоги в этом подкаталоге (OpenCode подгружает все `AGENTS.md` между целью чтения и рабочей директорией). Файлы комбинируются nearest-first — самый близкий к коду загружается раньше — и дедуплицируются, пока запись об их загрузке видна модели в истории.

Два практических следствия:

- Правка вложенного `AGENTS.md` **после его загрузки** не отслеживается автоматически — чтобы обновление применилось сразу, начните новую сессию.
- После компакции запись о загрузке может пропасть из истории, и при повторном чтении той же области файл будет подгружен снова — правила «переживают» сжатие.

### `references`: именованные внешние источники знаний

Секция `references` в `opencode.jsonc` даёт агенту **именованный** доступ к знаниям за пределами проекта: локальным каталогам или Git-репозиториям.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "product-specs": {
      "path": "docs/product-specs",         // локальный каталог (относительно конфига)
      "description": "Продуктовые правила каталога книг: квоты, лицензии, статусы",
    },
    // строковый шортхенд — когда достаточно только пути:
    "shared": "~/work/shared-docs",
    // Git-вариант — внешний репозиторий:
    // "effect": { "repository": "owner/repo", "branch": "main" },
  },
}
```

- `path` — локальный каталог: относительный (разрешается от каталога с конфигом), абсолютный или `~/...`; строковый шортхенд `"alias": "путь"` эквивалентен `{ "path": "путь" }`.
- `repository` (опционально с `branch`) — удалённый Git-репозиторий (`owner/repo`, Git URL, SCP-форма); без `branch` берётся ветка по умолчанию, чекауты кэшируются в глобальном каталоге данных и обновляются в фоне.
- `description` подсказывает агенту, **когда** использовать reference: references с описанием попадают в инструкции агента с алиасом и путём; без описания — доступны клиентам, но не рекламируются.
- Клиент прикрепляет reference по **алиасу**; в прикрепление попадает не-рекурсивный список корневых файлов и каталогов, а к содержимому ниже корня агента просят перейти явно («прочитай product-specs/download-policy.md»).
- References **не дают** дополнительных прав: доступ за пределами рабочей директории (Location) по-прежнему проверяется обычными правилами инструментов и permission `external_directory`; правка требует соответствующего edit-permission.

## Практика шаг за шагом

### Шаг 1. Создайте вложенный `AGENTS.md` для доменного пакета

Корневой `AGENTS.md` уже задает правила всего проекта (Урок 01). Теперь добавим правила именно для доменного пакета — они подхватятся лениво, когда агент начнет работать в `src/books_api/domain/`. Отправьте в чат:

```text
Прочитай текущий корневой AGENTS.md и структуру src/books_api/domain/.
Создай файл src/books_api/domain/AGENTS.md с правилами, специфичными именно для доменного пакета books-api:

1. Чистота домена: в src/books_api/domain/ разрешены импорты ТОЛЬКО из стандартной библиотеки Python (и внутри пакета). Никаких сторонних пакетов, никаких импортов из инфраструктуры.
2. Immutability: все Value Objects — только dataclass(frozen=True, slots=True); сущности изменяются только через явные методы домена, а не прямым присваиванием полей извне.
3. Экспорт публичного API: каждый новый публичный модуль обязан экспортировать свои публичные символы в src/books_api/domain/__init__.py с явным списком __all__.
4. Ошибки: любые нарушения доменных инвариантов — только подклассы DomainError из errors.py (например QuotaExceededError); никогда не выбрасывать голые Exception, ValueError или AssertionError.

Прочитай модули в src/books_api/domain/ и убедись, что текст правил соответствует фактическому коду, затем запиши файл.
```

Обратите внимание на транскрипт: агент прочитал файлы в `src/books_api/domain/`, и OpenCode при этом **сам подгрузил** новый вложенный `AGENTS.md` (вы увидите соответствующую запись в инструкциях). Перезапуск сессии не понадобился.

### Шаг 2. Настройте `compaction` и подключите `references` в `opencode.jsonc`

Теперь настроим compaction и продуктовую спецификацию. Отправьте агенту:

```text
1. Создай каталог docs/product-specs/ и файл docs/product-specs/download-policy.md с продуктовыми правилами квот скачивания для каталога свободных книг. Зафиксируй ровно такие правила:
   - Гость (неверифицированный читатель, is_verified=False): не более 3 скачиваний в сутки.
   - Верифицированный читатель (is_verified=True): не более 25 скачиваний в сутки.
   - Заблокированный читатель (is_suspended=True): 0 скачиваний, доступ запрещён полностью.
   - Повторное скачивание ТОЙ ЖЕ книги тем же читателем в те же сутки НЕ расходует дневную квоту (в том числе повторное скачивание в другом формате).
2. Добавь в корневой opencode.jsonc две секции:
   - "compaction": { "auto": true, "keep": { "tokens": 15000 } }
   - "references": { "product-specs": { "path": "docs/product-specs", "description": "Продуктовые правила каталога книг: суточные квоты скачивания, статусы читателей" } }
Сохрани файл валидным JSONC и проверь итоговый конфиг.
```

Проверьте из второго терминала, что конфиг слит корректно и reference видна:

```bash
opencode debug config | grep -A4 compaction
opencode debug config | grep -A6 references
```

> **Для справки:** если бы спецификации лежали в соседнем каталоге, хватило бы строкового шортхенда `"product-specs": "docs/product-specs"`, а для внешнего репозитория правил — варианта `"repository": "owner/repo", "branch": "main"`. Доступ к путям вне рабочей директории дополнительно проверяется permissions `external_directory`.

### Шаг 3. Чистая сессия + reference: реализуем сущность `Reader`

Создадим **новую** сессию, чтобы проверить, как знания подтягиваются артефактами, а не памятью чата. Нажмите `Ctrl+X N` (или выполните `/new`).

В новой сессии прикрепите reference: введите в промпте слово `product-specs` (алиас доступен в списке прикреплений) — или просто попросите агента сделать это. Отправьте промпт:

```text
Прикрепи reference product-specs, прочитай docs/product-specs/download-policy.md и реализуй на основе этих правил сущность Reader в src/books_api/domain/reader.py и тесты в tests/test_reader.py:
1. Reader — сущность домена: id, is_verified, is_suspended.
2. Проверка допуска к скачиванию с учётом того, сколько скачиваний читатель уже сделал за сегодня: suspended=True — всегда отказ (QuotaExceededError или специализированная ошибка); гость — максимум 3 скачивания в сутки; верифицированный — максимум 25.
3. Уже скачанные за сегодня book_id не расходуют квоту повторно: повторное скачивание той же книги (в том числе в другом формате) разрешено, пока читатель не заблокирован.
4. Тесты должны покрыть все три статуса читателя и правило повторного скачивания.
Перед завершением прогони just check и just test.
```

Понаблюдайте за работой агента:

- В инструкциях сессии появилась reference `product-specs` (с вашим описанием) — агент её прочитал и применил ровно ваши квоты: 3 / 25 / 0.
- Когда агент начал читать файлы в `src/books_api/domain/`, OpenCode подтянул вложенный `AGENTS.md` — и агент экспортировал публичные символы `Reader` в `__init__.py` с `__all__`, а нарушения квот оформил через подкласс `DomainError`.
- Все числа квот пришли из `docs/product-specs/download-policy.md` — артефакта, а не из разговоров прошлых сессий.

### Шаг 4. Управление сессиями: переименуйте, закрепите, вернитесь

Поэкспериментируйте в TUI:

1. `Ctrl+R` — переименуйте текущую сессию, например в «Reader: квоты скачивания». Осмысленное имя окупается, когда в `/sessions` десятки сессий.
2. `Ctrl+F` — закрепите сессию: в списке `/sessions` она всегда будет наверху.
3. `Ctrl+X N` — создайте ещё одну сессию, отправьте туда любой вопрос. Переключайтесь между вкладками `Ctrl+Tab` / `Ctrl+Shift+Tab`, закройте лишнюю вкладку `Ctrl+X W`.
4. `Ctrl+O` — откройте меню недавних сессий и проектов; найдите сессии уроков 01–03 и вернитесь в любую из них (`Ctrl+X L` открывает полный список).
5. Во втором терминале посмотрите на те же сессии глазами сервера:

```bash
opencode session list
opencode session list --format json | head -40
```

### Шаг 5. Compaction вручную и экспорт сессии

Убедимся, что компакция работает и как выглядит её результат:

1. Вернитесь в сессию «Reader: квоты скачивания» и нажмите `Ctrl+X C` — сессия будет сжата независимо от её текущей длины. Отправьте после этого мелкий вопрос:

```text
Кратко: какие суточные квоты скачивания у гостей и верифицированных читателей?
```

Агент ответит правильно: числа живут в `docs/product-specs/download-policy.md` и в коде `reader.py`, а не только в «истории чата» — они пережили сжатие.

2. Выгрузите сессию с маскированием чувствительных данных и посмотрите формат:

```bash
opencode session export "$(opencode session list --max-count 1 --format json | head -1)" --sanitize > /tmp/opencode/reader-session.json 2>/dev/null || opencode session export --sanitize > /tmp/opencode/reader-session.json
head -30 /tmp/opencode/reader-session.json
```

(Проще всего взять ID из вывода `opencode session list` и подставить его явно: `opencode session export ses_xxxx --sanitize`.)

3. Уберите мусорные сессии-эксперименты из Шага 4, если они создавались: `opencode session delete ses_xxxx`.
