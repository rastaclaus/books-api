# Урок 04. Проектная память и управление сессиями

[← Урок 03. Планирование и управление ходом](03-planning-todos-and-flow-control.md) | [Карта курса](README.md) | [Урок 05. Проектные скиллы →](05-project-skills.md)

## Цель урока

- Освоить долговременную память `jcode`: разницу между **`project`** и **`global`** областями, slash-команду `/memory` и CLI-инструменты `jcode memory`.
- Научиться управлять жизненным циклом сессий: закладки `/save`, интерактивный пикер `/resume`, переименование `jcode session rename` и сжатие контекста `/compact`.
- Зафиксировать в проектной памяти политику антибот-защиты `books-api` и реализовать сущность `Reader` с дневными лимитами скачиваний.

---

## Теория-минимум: чем проектная память отличается от `AGENTS.md`

Новички часто путают `AGENTS.md` и память (`memory`). Вот простое правило разделения:

| Характеристика | `AGENTS.md` и `.jcode/*.md` | Память проекта (`memory` со `scope="project"`) |
|---|---|---|
| **Где хранится** | Внутри репозитория (обычно в Git) | Локально в `~/.jcode/memory/projects/<hash-рабочей-папки>.json` (глобальная память лежит в `~/.jcode/memory/global.json`) |
| **Когда загружается** | Всегда целиком в статический системный промпт | Подбирается по релевантности к текущему запросу или вызывается агентом явно (`remember`, `recall`, `search`, `list`) |
| **Что хранить** | Незыблемые правила для всех: стек, структуру папок, команды `just check` / `just test` | Накопленные знания по ходу разработки: принятые доменные компромиссы, корнер-кейсы, связи сущностей, личные поправки (`fact`, `preference`, `entity`, `correction`) |

У каждого воспоминания есть категория (`fact`, `preference`, `entity`, `correction`), теги и графовые связи (`link` / `related`). При этом локальные операции (`remember`, `list`, поиск по ключевым словам, `forget`, `export`/`import`) работают полностью автономно на вашей машине.

### Как не потеряться в десятках сессий

- `/save [метка]` добавляет текущую сессию в избранный блок («Saved») интерактивного меню `/resume` (`/unsave` убирает закладку).
- `/resume` (или запуск `jcode --resume` из терминала) открывает быстрый пикер всех сессий с предпросмотром: `Enter` переключает текущий терминал, `Ctrl+Enter` открывает сессию в новом окне терминала.
- `jcode session rename <session_id> "<новое имя>"` позволяет дать важной сессии понятный заголовок из CLI.
- `/compact` сжимает разросшуюся историю длинной сессии в компактное резюме, освобождая окно контекста без потери сути разговора.

## Практика шаг за шагом

### Шаг 1. Проверьте статус памяти и сохраните доменные решения проекта

В открытой TUI-сессии `jcode` проверьте состояние подсистемы памяти:

```text
/memory status
```

(Если память вдруг была выключена, включите её командой `/memory on`).

Теперь представим реальную рабочую ситуацию: продуктовая команда договорилась о правилах раздачи книг читателям, чтобы боты не выкачивали весь архив в один поток. Попросите агента сохранить эти факты **именно в проектную память** (`scope="project"`):

```text
Запомни в проектную память (scope="project") с тегами `quota`, `reader`, `policy` следующие продуктовые правила books-api:
1. Каталог бесплатный, но для защиты от ботов действует суточная квота скачиваний на читателя: гость или неверифицированный читатель (`is_verified=False`) может скачать не более 3 книг в сутки, а читатель с подтверждённым email (`is_verified=True`) не более 25 книг в сутки.
2. Заблокированный читатель (`is_suspended=True`) не может скачивать книги вообще, независимо от оставшейся квоты.
3. Повторное скачивание той же самой книги тем же читателем в течение тех же суток НЕ расходует суточную квоту повторно (читатель просто перекачивает другой формат, например PDF после EPUB).
```

Обратите внимание, что агент вызовет встроенный инструмент `memory` с `action="remember"`, `scope="project"` и категорией `fact`.

### Шаг 2. Проинспектируйте память из второго терминала через CLI

Не выходя из `jcode`, переключитесь во второй терминал в папке `books-api` и выполните:

```bash
jcode memory stats
jcode memory list
jcode memory search quota
```

Вы увидите сохранённые записи, их ID, категории и теги! При необходимости память проекта можно даже выгрузить в JSON для бэкапа (`jcode memory export backup-memory.json`).

### Шаг 3. Сделайте закладку сессии и проверьте перенос знаний в НОВУЮ сессию

В текущем окне `jcode` добавьте сессию в закладки:

```text
/save book-aggregate-session
```

Теперь намеренно начните **чистую новую сессию** (перезапустите `jcode` или откройте новую сессию, где в истории чата нет ни слова про числа `3` и `25`), и дайте задачу без пересказа продуктовых цифр:

```text
Вспомни из проектной памяти наши продуктовые правила по читателям и суточным антибот-квотам скачиваний.
На основе этих правил реализуй в `src/books_api/domain/reader.py` сущность `Reader` (и при необходимости Value Object / метод проверки допуска к скачиванию книги с учётом уже скачанных за сегодня `book_id`), а также тесты в `tests/test_reader.py`.
```

Посмотрите, что произошло:

- Агент обратился к проектной памяти, достал точные лимиты (`3` для неверифицированных, `25` для верифицированных, запрет при `is_suspended=True` и бесплатное повторное скачивание другого формата той же книги за сутки) и реализовал код и тесты один в один по сохранённым правилам!

### Шаг 4. Испытайте пикер `/resume` и `/compact`

Проверьте управление сессиями на практике:

1. Введите `/resume`: вверху списка вы увидите сохранённую закладку `book-aggregate-session`, а также вашу текущую сессию по `Reader`. Нажмите `Esc`, чтобы закрыть пикер, оставшись в текущей сессии.
2. Посмотрите ID текущей сессии через `/info` и во втором терминале попробуйте переименовать её:
   ```bash
   jcode session rename <SESSION_ID_ИЗ_INFO> "Domain: Reader & Daily Quotas"
   ```
3. Если диалог стал длинным, протестируйте `/compact`, а затем закоммитьте сущность `Reader` и её тесты:
   ```text
   /commit
   ```

## Самопроверка

Выполните в терминале:

```bash
jcode memory list
just check
just test
```

Чеклист результата:

- [ ] `jcode memory list` показывает проектные правила квот с тегами `quota` / `reader`.
- [ ] Сущность `Reader` корректно даёт квоту `3` неверифицированному читателю, `25` верифицированному, `0` заблокированному и не списывает квоту дважды за одну и ту же книгу в пределах одних суток.
- [ ] Оба контура (`just check` и `just test`) проходят без единого замечания.

## Шпаргалка урока

| Команда | Назначение |
|---|---|
| `/memory [on\|off\|status\|extract]` | Управление памятью в текущей сессии и планирование фонового извлечения знаний |
| `jcode memory list` / `search <q>` / `stats` | Просмотр, поиск и статистика памяти из CLI |
| `jcode memory export <file.json>` | Экспорт графа памяти в JSON |
| `/save [label]` и `/unsave` | Закрепить или открепить важную сессию в верхней секции пикера `/resume` |
| `/resume` (или `jcode --resume`) | Интерактивный переключатель сессий (`Enter` в этом окне, `Ctrl+Enter` в новом) |
| `jcode session rename <id> "<title>"` | Задать человекочитаемое имя сохранённой сессии |
| `/compact` | Сжать историю текущей сессии без потери ключевого контекста |
