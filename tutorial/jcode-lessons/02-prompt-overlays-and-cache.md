## Теория-минимум: слои `.jcode/` и почему важен prompt-кэш

В Уроке 01 мы создали `AGENTS.md`. Зачем нужны дополнительные файлы в папке `./.jcode/`?

| Файл проекта | Глобальная пара | Как работает | Когда использовать |
|---|---|---|---|
| `./AGENTS.md` | `~/AGENTS.md` | Добавляется к базовому промпту (оба файла, если оба существуют) | Общие правила репозитория для всей команды и любых AI-инструментов |
| `./.jcode/prompt-overlay.md` | `~/.jcode/prompt-overlay.md` | Добавляет инструкции поверх базового промпта и `AGENTS.md` | Специфичные для `jcode` рабочие привычки, стиль ответов или ваши локальные правила (можно добавить в `.gitignore` или закоммитить) |
| `./.jcode/preferred-tools.md` | `~/.jcode/preferred-tools.md` | Добавляет блок приоритетов по выбору инструментов | Указания, какими именно тулами и командами пользоваться в этом репо (`agentgrep` вместо `bash grep`, `just check` и `just test` вместо сырых вызовов) |
| `./.jcode/system-prompt.md` | `~/.jcode/system-prompt.md` | **Полностью заменяет** встроенный базовый промпт (слой 1). Пустой файл безопасно игнорируется | Редкие случаи, когда из `jcode` нужно сделать узкоспециализированного бота (при этом `AGENTS.md`, оверлеи и скиллы всё равно продолжат применяться) |

### Как это связано с prompt-кэшем

Статические слои (`system-prompt`, `AGENTS.md`, `prompt-overlay.md`, `preferred-tools.md`) собираются один раз при старте сессии и образуют **неизменный префикс запроса**. Благодаря этому провайдер (Anthropic или OpenAI) кэширует весь системный промпт и описания инструментов: начиная со второго хода сессии вы платите на порядок меньше токенов и получаете быстрый отклик (`TTFT`).

Команда `/cache stats` (и `/info`) позволяет прямо в TUI видеть счётчики `cache_read` / `cache_write`. Если кэш «остыл» после долгой паузы, `jcode` даже умеет предупреждать об этом уведомлением, а для Anthropic длину жизни кэша можно настроить командами `/cache 1h` или `/cache 5m`.

## Практика шаг за шагом

### Шаг 1. Создайте `.jcode/preferred-tools.md` и `.jcode/prompt-overlay.md`

Мы не будем трогать `.jcode/system-prompt.md` (стандартный базовый промпт `jcode` отлично сбалансирован для разработки), а вот два оверлея создадим прямо сейчас.

В терминале или попросив агента (либо создав файлы вручную), добавьте две настройки проекта:

**1. Файл `.jcode/preferred-tools.md`** (правила выбора инструментов в `books-api`):

```markdown
# Предпочтительные инструменты для books-api

- Для поиска символов, классов и файлов по проекту всегда используй `agentgrep` (`mode="grep"`, `mode="find"`, `mode="outline"`), а не `grep`/`find` через `bash`.
- Для точечных правок существующих модулей используй `edit` или `apply_patch`, никогда не переписывай файлы через `python -c` или `sed` в `bash`.
- Для проверки качества и тестов используй рецепты `justfile`: `just check` (прогон `ruff check`, `ruff format --check` и `ty check`) и `just test` (короткий прогон `uv run pytest -q`), а для автоформатирования вызывай `just fmt`.
```

**2. Файл `.jcode/prompt-overlay.md`** (тонкая настройка стиля моделирования домена и финишной самопроверки):

```markdown
# Правила моделирования Value Objects и сдачи задач

- Все Value Objects делай неизменяемыми (`@dataclass(frozen=True, slots=True)`), валидацию инвариантов выполняй в `__post_init__`.
- Нормализуй входные строки в Value Objects (например, убирай крайние пробелы и приводи коды языков/ISBN к каноническому виду) до проверки инварианта, используя `object.__setattr__(self, ...)` внутри `__post_init__`.
- Держи модули компактными и без преждевременных абстракций: никаких фабрик ради фабрик и метаклассов; выноси нетривиальные числовые пороги и длины в именованные константы (чтобы код проходил строгий `ruff` без лишних `# noqa`).
- Никогда не сдавай задачу без финального прогона `just check` и `just test`: в конце каждого ответа давай краткую сводку (до 5 строк), какие инварианты добавлены и каков статус `just check` / `just test`.
```

### Шаг 2. Начните новую сессию и проверьте сборку слоёв

Запустите свежую сессию `jcode` (или выполните перезапуск клиента, чтобы создалась новая сессия) и проверьте:

```text
/context
```

Убедитесь, что в статическом системном промпте присутствуют все три проектных блока в правильном порядке:
1. `AGENTS.md`
2. `.jcode/prompt-overlay.md`
3. `.jcode/preferred-tools.md`

Заодно проверьте быстрые настройки скорости и глубины рассуждений текущей сессии:

```text
/effort
/fast status
```

- `/effort` показывает (или меняет, например `/effort medium` / `/effort high`) бюджет рассуждений модели: для рутинных Value Objects достаточно среднего уровня, а для сложной архитектуры в следующих уроках можно поднять его выше.
- `/fast status` показывает текущий сервисный тир провайдера (`/fast on`, `/fast off`, `/fast flex`).

### Шаг 3. Создайте Value Objects домена `books-api`

Отправьте в `jcode` задачу на создание первых кирпичиков предметной области:

```text
Реализуй в `src/books_api/domain/value_objects.py` Value Objects для каталога свободных электронных книг и покрой их тестами в `tests/test_value_objects.py`:

1. `BookFormat` (StrEnum): допустимые форматы раздачи `EPUB`, `PDF`, `MOBI`.
2. `LanguageCode`: неизменяемый Value Object для двухбуквенного ISO-кода языка (например, `"ru"`, `"en"`). Приводит строку к нижнему регистру, обрезает пробелы и выбрасывает наследника `DomainError` (например, `ValidationError`), если код не состоит ровно из 2 латинских букв.
3. `ISBN`: неизменяемый Value Object, принимающий ISBN-10 или ISBN-13 (с дефисами/пробелами или без них). Сохраняет каноническую строку без разделителей и валидирует длину и контрольную цифру (при ошибке выбрасывает `ValidationError`).
4. `LicenseType` (StrEnum): только открытые и свободные лицензии для легальной бесплатной раздачи: `PUBLIC_DOMAIN`, `CC0`, `CC_BY`, `CC_BY_SA`. Добавь удобные свойства `requires_attribution: bool` (`True` для `CC_BY` и `CC_BY_SA`) и `is_share_alike: bool` (`True` только для `CC_BY_SA`). Попытка передать любую несвободную строку при разборе должна приводить к `LicenseViolationError`.

Экспортируй созданные типы в `src/books_api/domain/__init__.py` и убедись, что проект готов к сдаче.
```

Обратите внимание, как сработали ваши оверлеи без единого напоминания про инструменты в тексте задачи:

1. Модели не пришлось объяснять про `@dataclass(frozen=True, slots=True)`, именованные константы для `ISBN` и `object.__setattr__` в `__post_init__`: она взяла этот паттерн из `.jcode/prompt-overlay.md`.
2. Перед завершением агент сам прогнал и линтеры/тайпчекер (`just check`), и юнит-тесты (`just test`) согласно `.jcode/preferred-tools.md` и `.jcode/prompt-overlay.md`.
3. Финальный ответ получился сжатым и по делу.

### Шаг 4. Посмотрите на работу prompt-кэша вживую

Сразу после завершения хода выполните в TUI:

```text
/cache stats
```

И сравните с `/info`. Вы увидите реальные метрики кэширования вашего провайдера (`cache_read_tokens` / `cache_write_tokens` или долю закэшированного входного префикса). Попросите агента добавить ещё один маленький тест (например, проверку `ISBN` с контрольным символом `'X'` в ISBN-10) и снова вызовите `/cache stats`: статический префикс с `AGENTS.md` и обоими файлами `.jcode/*.md` переиспользуется из кэша!

Зафиксируйте прогресс коммитом:

```text
/commit
```
