# Domain style — books-api

Правила для кода в `src/books_api/domain/`. Чистый Domain Layer: без HTTP, ORM/SQL и внешних зависимостей. Python 3.14, строгая типизация, `@override` при переопределении.

## Value Objects

- Любой VO — `@dataclass(frozen=True, slots=True)`; неизменяемость и отсутствие `__dict__` обязательны.
- Порты репозиториев — `typing.Protocol`, перечисления — `Enum`/`StrEnum`.
- VO не знает о хранилище, времени и I/O: только свои данные и инварианты.

## Инварианты

- Вся валидация — в `__post_init__`; объект не должен существовать в невалидном состоянии.
- Нарушение инварианта → исключение, унаследованное от `DomainError` (`books_api.domain.errors`):
  `ValidationError` для неверных входных данных, специализированные наследники (`InvalidBookStateError`, `LicenseViolationError`, `QuotaExceededError`) — когда причина бизнес-специфична.
- Общий `Exception`, `ValueError`, `AssertionError` в домене не бросаем; сообщение — конкретное, с именем поля и значением.

## Нормализация

- Обрезка пробелов, приведение регистра и т.п. — только в `__post_init__` через `object.__setattr__(self, "field", normalized)`.
- Иначе никак: прямое присваивание в frozen-датаклассе запрещено. Сначала нормализовать, затем валидировать нормализованное значение.
- Нормализация должна быть идемпотентной: `VO(VO(x).field).field == VO(x).field`.

## Константы

- Любой порог, лимит, допустимое множество значений — именованная константа уровня модуля (`MAX_TITLE_LENGTH`, `ALLOWED_LICENSES`), в `UPPER_SNAKE_CASE`.
- «Волшебных чисел» и инлайн-литералов в проверках нет; константа называется по смыслу, а не по значению.

## Фабрики

- Фабрики не создаём ради фабрик: если конструктор вызывается напрямую и без сложной сборки, используем его.
- Отдельный фабричный метод/класс — только при реальной нужде: несколько шагов с I/O, выбор подкласса, разбор внешнего формата. Причина фиксируется докстрингом.
